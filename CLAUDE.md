# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

InstantOS is a graphical x86_64 hobby OS. It boots under UEFI, ships a C++ kernel, a userland of system "manager" services and GUI apps, and ports of real software (mlibc, GNU bash, coreutils, TinyCC, binutils, GCC, NetSurf). The long-term goal is a GCC that rebuilds itself inside InstantOS (see `roadmap.txt`, which tracks phases P0–P7). `TODO.md` lists the remaining work.

## Build environment

- The build runs on Linux, normally **WSL2 Ubuntu at `/mnt/d/projects/InstantOS`** (see `docs/wsl-setup.md`). The Windows checkout is the same tree. Scripts expect Arch-style OVMF paths (`/usr/share/edk2/x64/OVMF_{CODE,VARS}.4m.fd`). On Ubuntu, symlink them.
- Toolchain: clang/clang++, lld/lld-link, nasm, cmake, meson, xorriso, mtools, qemu. The bash/mlibc port needs clang >= 19 (`export PATH=/usr/lib/llvm-20/bin:$PATH`).
- Submodules are required, including the nested ones: `outside/iboot` (the bootloader), `outside/iUserApps` (userland), and inside it `outside/iUserApps/outside/{ilibcxx,mlibc,mlibc-sysdeps,tinycc}`.
- Keep heavy build trees (GCC/binutils) in WSL, not in the Windows `build/` directory, because C: is short on space.
- In this Windows checkout, `git status` shows almost every file as modified only because of file mode (755→644) and CRLF changes. Look at `git diff --stat` to find the real content changes.

## Commands

```bash
# Configure + build kernel, bootloader, userland, initrd, ISO -> build/iboot.iso
cmake -S . -B build [-DINSTANTOS_ENABLE_TCC=ON]
cmake --build build --target iso --parallel 4

# All in one: clean, optionally build mlibc+bash (cached in .bash-cache/; BASH_FORCE=1 rebuilds), build, run
./build.sh            # ENABLE_BASH=auto|0|1, ENABLE_TCC=auto|0|1

# Run in QEMU (serial -> serial.log, QEMU debug -> qemu.log)
./run.sh                                              # USB_MODE=xhci|ohci|none, GPU_MODE=plain|venus
QEMU_ACCEL=tcg QEMU_DISPLAY=none USB_MODE=xhci ./run.sh   # headless; WSL has no KVM, so always use tcg there
./run-win.sh                                          # Windows-native QEMU (WHPX) from Git Bash

# Kernel only (faster iteration)
cmake --build build --target INSTANTOS.EFI BOOTX64.EFI mkInitrd_proj
```

There is no lint step and there are no unit tests in the usual sense. Verification works like this:
- **Smoke tests** (`tools/run-*-smoke.sh`, e.g. `run-tcc-smoke.sh`, `run-coreutils-smoke.sh`, `run-bash-smoke.sh`, `run-pty-smoke.sh`, `run-storage-smoke.sh`, `run-network-smoke.sh`) build a custom ISO, boot it headless under QEMU with a timeout, and grep the serial log for marker strings. A run fails if the log contains `Unknown Instruction` or `User process crash`. Each script checks its prerequisites (bash, mlibc, tcc artifacts in `build/`) and says which `tools/build-*.sh` to run. To run a single test, run that one script.
- **In-OS feature suite**: `tools/run-os-testsuite.sh` builds the suite ISO (`tools/os-testsuite/build-testsuite-iso.sh`, whose `/bin/login` is `runner.c`) and an ext4 disk, boots them headless, and exits 0 only if the `[ostest] SCORE ... fail=0` line appears. `SKIP_BUILD=1` reuses the existing ISO; `SKIP_CMAKE=1` repacks only `runner.c`. The roadmap rule is that nothing counts as done until it runs headless in QEMU and this suite stays fully green.
- **Network suite**: `tools/run-net-suite.sh` boots an ISO whose `/bin/login` is `tools/net-suite/netsuite.c`, using the same build as the feature suite and the shared header `tools/os-testsuite/ostest.h`. It tests ping, UDP/TCP echo and HTTP downloads against `tools/net-suite/host_server.py`, which QEMU user networking exposes to the guest as 10.0.2.2. With `NET_INTERNET=1` it also does DNS and HTTP to example.com and runs the mlibc `dns-smoke`/`http-smoke` apps. `QEMU_NIC` swaps the NIC (for example `e1000`, `e1000e`, or `virtio-net-pci,vectors=0` to test INTx); with the default NIC the run also requires virtio-net's MSI-X line in the log. By default the NIC is a socket netdev to `host_server.py --link`, which relays frames to slirp (on a hub with a second socket netdev) and can drop, duplicate, reorder and delay TCP on the guest's request; it also plays a fake host, 10.0.2.77, that sends the ICMP errors, pings and probes slirp cannot and reports the options of our SYN (`NET_LINK=0` puts the NIC straight on slirp). The relay halves throughput, so compare speeds with `NET_LINK=0`. `run-os-testsuite.sh` takes the backend as `QEMU_NETDEV`. When bash and the network tools are built the suite also runs them (through `bash -c`, output captured) against the host, the fake host's DNS zone (`*.test`) and NTP server, and, with `NET_INTERNET=1`, example.com. With an mbedTLS curl it also tests https:// against `host_server.py --https`, using a test CA and server certificate it makes with openssl in `build/net-suite/tls` (bundled as `/etc/ssl/test-ca.pem`), plus the system bundle against real sites with `NET_INTERNET=1`. The host also pulls the guest's cable over QMP (`GET /linkflap/MS` -> `set_link net0`) and checks the link and lease come back, and the suite checks `KernelLog`/`dmesg`. Any QEMU NIC model works (`e1000`, `e1000e`, `igb`, `rtl8168` with the custom QEMU). It passes only with `fail=0`; `GAP:` lines record known shortcomings without failing the run.
- **NetSurf suite**: `tools/run-netsurf-suite.sh` boots the real system image (cmake writes its entry list to `build/initrd-entries.txt`) with `/bin/login` swapped for `tools/netsurf-suite/driver.c`, which gives NetSurf a homepage on `host_server.py --https` and starts the compositor. `tools/netsurf-suite/drive.py` then works the VM over QMP like a user (relative USB mouse moved in steps after homing at (0,0), `send-key`): clicks the taskbar's Web slot, checks the page, stylesheet and image are fetched over HTTPS (`--request-log`) and drawn (exact colours from `tools/netsurf-suite/pages/style.css` in screendumps), clicks a link, types a URL, types another with Shift held over several keys (`input-send-event`), and edits one with Home/End/Left/Delete. Screendumps and logs land in `build/netsurf-suite`. QMP's Unix socket must live outside `/mnt/d` (drvfs cannot hold one).
- Every QEMU launcher takes `QEMU_SMP` for the CPU count. The default is 2, except 1 for `run-os-testsuite.sh` and `run-win.sh`.
- **Keyboard suite**: `tools/run-kbd-suite.sh` boots QEMU with each keyboard (`KBD_MODES`, default `ps2 usb ohci`: the i8042 alone, usb-kbd on xHCI, on OHCI) and presses keys over QMP (`tools/kbd-suite/drive.py`). A probe image (the feature suite's, `/bin/login` = `tools/kbd-suite/console_probe.c`) prints each console read in hex, which is compared with the bytes every kind of key must give. The system image (`build/iboot.iso`, needs bash and curl) opens the terminal and edits bash command lines with the keys (arrows, Home/End, Delete, Ctrl+A/K/W/C, Ctrl+Left/Right, Alt+B, held Shift, repeat, keypad, Caps/Num Lock); each line is a curl to `host_server.py`, whose request log shows what bash ran. When the QEMU (`QEMU`, default `~/qemu-rtl`'s if built) has the `hid_kbd_set_leds` trace event it also checks the lock lights. `KBD_PARTS=console|terminal` runs one half. Passes only with `[kbdsuite] SCORE ... fail=0`.
- **Host-side fixtures**: `tools/run-acpi-fixtures.sh` (ACPI table parsing), `tools/run-keymap-fixtures.sh` (the keyboard tables in `keymap.hpp`: PS/2 codes, repeat, keypad, US text, console bytes for every key and modifier), `tools/run-i915-fixtures.sh` (the Intel Gen9 driver's pure logic in `intel_gen9_logic.hpp`: device ids, BAR/plane/GGC decoding, GGTT entries, the GTT page allocator against a model, the private PAT, PPGTT entries and 4-level contexts, the workaround tables, fuse decoding, null-state relocation and ring commands; register values from the HD 530 PC) and `tools/ext4-fixtures/`.

## Architecture

**Boot chain:** UEFI firmware → `BOOTX64.EFI` (iboot submodule) → `INSTANTOS.EFI`. The kernel is itself a PE/COFF UEFI application (clang `-target x86_64-unknown-windows`, `lld-link`, entry symbol `InstantOS`, NASM `win64` objects). iboot passes a `BootInfo` that holds the framebuffer, memory map, RSDP and initrd location. `iboot::headers` provides the shared BootInfo types.

**Kernel** (`src/`, headers in `include/` mirror the same tree). `CMakeLists.txt` globs every `src/**/*.cpp|*.asm`, so new files need no CMake edits. It is freestanding C++23: no RTTI, no exceptions, no libc/libstdc++, built with `-Oz -fno-inline`. Use the in-tree helpers in `include/common/`. Most subsystems are singletons reached through `X::get()`. `src/main.cpp` (`InstantOS(BootInfo*)`) sets the init order: console → GDT → CPU features → PMM/VMM → 16 MiB heap → ACPI → APIC → scheduler → timers → USB/I2C input → GPU (virtio-gpu, VirGL/Venus, SVGA, Intel probes) → syscalls → SMP AP startup (`src/cpu/smp.cpp`; the APs wait until `SMP::startScheduling()` at the end of boot) → users/sessions → VFS mounts → seeding of `/etc` files → launch of the userland services. The same sources also build `INSTANTOS_INPUT_PROBE.EFI` (with `INPUT_PROBE_ONLY=1`), a diagnostic kernel for input hardware.
- `cpu/`: ACPI (with an AML interpreter; pure table logic lives in `acpi_tables.hpp` so host fixtures can share it), APIC/IOAPIC, GDT/IDT/ISRs, per-CPU data, `process/` (scheduler, context switch, ELF/PE exec), `syscall/` (split by area: fs, mem, proc, …), tty/PTY, users/sessions.
- **SMP and locking:** every CPU listed in the MADT runs the scheduler. All kernel code runs under one recursive big kernel lock (`include/cpu/klock.hpp`). It is taken at syscall, IRQ and exception entry, dropped when returning to user mode (including the trampolines in `process/switch.cpp`) and at the top of `idleLoop`, and handed across `switchContext` by `Scheduler::switchTo`. Kernel code must not wait for an interrupt while holding it. In the kernel, GS always points at the executing CPU's `PerCPUData` (`include/cpu/percpu.hpp`), so never cache per-CPU pointers across a context switch. Threads of one address space run on several CPUs at once, so any change that removes or narrows a mapping must go through `TLB::shootdown` (`include/cpu/tlb.hpp`). The VMM unmap/protect/COW paths and fork already do. Do not free a frame or page table until the shootdown has returned, and never spin with interrupts off without calling `TLB::pollPending()`. Widening a mapping needs no shootdown: the page-fault handler retries stale-TLB faults. `exec` sends SIGKILL to the caller's other threads and waits until they are reaped (`Scheduler::killSiblingThreads`) before it swaps the image, because their teardown unmaps from the shared address space. A timer or IPI that interrupts user mode acts on a pending SIGKILL (`Process::terminateIfKilled`). Like Linux `exit_group`, `Exit`, a fatal signal or a crash in any thread ends the whole process (`Scheduler::exitThreadGroup`): the main thread keeps the exit status, and `wait` reports it only once every thread has been reaped. `ThreadExit` ends just the calling thread, except on the main thread, where it acts like `Exit`. Two things already run without the BKL:
  - Scheduler ticks that would change nothing (`Scheduler::tickIsNoop`, plus the boot CPU's `tryEnter` tick).
  - Block-backed filesystems. ext4/FAT32 VNode ops, mount, format and the AHCI driver run under the storage lock (`include/fs/storage/storage_lock.hpp`), and syscalls on the `storageMayRunUnlocked` list (`syscall.cpp`) release the BKL for the whole operation. Code reachable from there may only use subsystems with their own locks (heap, PMM, console), never BKL-protected state. Lock order is BKL, then storage. A syscall added to that list must hold no unpinned pointer to BKL state across VFS calls; fds are pinned with `PinnedFd`. The storage lock belongs to a CPU and its holder polls the disk with interrupts off, so it never sleeps; a contender that gave up the BKL for its Section spins 2 ms and then sleeps 1 ms between tries (`Section::acquire`), any other contender spins. AHCI logs a command that takes 500 ms or more (`took N ms`): a hard disk spinning up takes seconds.

  `KLOCK_PROFILE` in `klock.cpp` prints per-entry-site contention.

  Device interrupts are spread over the APs: `APICManager::mapGSI` and `PCI::registerMSIInterrupt` record each route with `IRQBalance` (`include/cpu/apic/irq_balance.hpp`), and `SMP::startScheduling` moves them round-robin off the boot CPU, which keeps the PIT tick. IRQ handlers must therefore work on any CPU. The boot CPU's tick duties (USB polling, key repeat, waking sleepers, the network timers) are run by an AP's tick instead when the boot CPU has not run them for 4 ms (`timer_run_overdue_duties` in `tsc_timer.cpp`), e.g. while it polls a slow disk; a stand-in of 250 ms or more is logged when its tick is back (`[timer] the boot CPU's tick was out for …`). A handler on a vector of its own (MSI/MSI-X, or a `_PRT` GSI registered with `ISR::registerIRQ`) must send the EOI itself; on a shared INTx line (`registerLegacyInterrupt`) the dispatcher sends it and the handler must not. A missing EOI leaves the vector in service, which blocks every lower vector on that CPU: on the boot CPU that is its timer (0x40), so the clock, input polling and wake-ups stop (on a real PC the xHCI MSI did this once at boot; under QEMU it happened to land on an AP). Each thread has a CPU affinity mask (`Process::cpuAffinity`, the `SchedSetAffinity`/`SchedGetAffinity`/`GetCpu`/`CpuInfo` syscalls) that `Scheduler::getNextProcess` honours. mlibc's `sysconf(_SC_NPROCESSORS_ONLN)` asks `CpuInfo`.
- `fs/`: a VFS with initrd (read-only `/bin` and `/lib`), RamFS (`/tmp`), devfs, FAT32 and ext4 on AHCI with partition parsing. Without a disk nothing is mounted at `/`; it is then a built-in read-only directory (`MountRootFS` in `vfs.cpp`) that lists the top-level mount points. Which disk becomes `/` (`main.cpp`, every AHCI port): on a GPT disk, a real computer's disk shared with other systems, only an InstantOS partition is ever mounted (`gptFindInstantOSPartition`: type `9566fa50-7665-4f44-962e-113fd99cdc87`, or a Windows basic-data partition holding FAT32 labelled `INSTANTOS`), and it wins; disks without GPT (the test images: MBR or a bare ext4 volume) are used as before. Boot writes to `/` (the `/etc` files, the ext4 self-test), so this rule is what keeps a PC's other systems safe. The FAT32 driver writes 8.3 names only and matches names without regard to case (`fatNameEquals`; an uppercase name used to miss its entry and get a second, empty one). Every disk command is a seek on a hard disk and runs with interrupts off, so the FAT32 driver keeps them few: a cluster (or a run of adjacent ones) is one device call, FAT sectors go through a small write-through cache (all FAT copies written from it), free clusters are searched from where the last search ended, writes touch only the sectors they change, and the directory entry is rewritten (one sector) only when the size or first cluster changed. It used to take 60-70 commands to append a line to `/kernel.log`.
- **Real hardware**: `tools/install-esp-windows.ps1` (Administrator) installs onto the EFI partition of the Windows PC this is developed on: it makes the `INSTANTOS` FAT32 partition (shrinking D:), backs the ESP up to `D:\InstantOS-ESP-backup`, copies `\EFI\InstantOS\iboot.efi` and `\EFI\BOOT\INSTANTOS.EFI`/`INITRD` only, and adds an InstantOS firmware boot entry. With an InstantOS partition mounted the kernel starts `log-saver`, which keeps the kernel log in `/kernel.log` (new lines appended every 250 ms, a heartbeat each second; the last boot's is `/previous.log`), readable from Windows. `tools\pc-run.ps1 [-NoReboot] 'cmd' ...` (Windows) runs commands on the PC unattended: it writes them to `F:\AUTORUN.SH`, which `login` renames to `/autorun.old` and runs with bash once the compositor is up (output in `/autorun.log`), ending with `reboot`; the firmware's BootNext (`tools\reboot-to-instantos.ps1`) then brings Windows back. Redirect each command's output to a file at the root (`> /OUT.TXT`) to read it from Windows. `reboot` (and `poweroff`, `reboot -p`) in the terminal restarts it without the power button: the root-only `Reboot` syscall flushes the drives' caches, then tries the FADT reset register, the keyboard controller, port 0xCF9 and a triple fault in turn. The PC has no serial cable: the kernel drives COM1 only under a hypervisor (CPUID's hypervisor bit; `Cereal::initialize`), since on bare metal every character waited for an idle 38400-baud UART with interrupts off (about 20 ms a log line), so there the log is the ring alone. QEMU cannot emulate its Intel HD 530, so GPU work is checked there (`[i915]` lines in the log). For lock-ups, `cpu/watchdog.cpp` runs on the APs' timer: when the boot CPU's tick stops for 2 s it NMIs it and draws a red banner without locks (its RIP as a `kernel.map` address, the big kernel lock's owner, the process and syscall, its LAPIC's TPR/PPR/ISR/IRR, the vectors it took, the disk command in flight) and redraws a live disk line; a stall that ends is also written to the kernel log. Its i3-6100's microcode predates the TSC-deadline erratum fix, so the tick is the PIT there (`tsc_deadline_has_errata`, Linux's table). The Intel driver (`intel_gen9*.cpp`, after i915) only reads the GPU at boot; anything that writes to it is an experiment run from the terminal with `/bin/gpu-test` (`info`, `gtt`, `flip [secs]`, `engine`, `hang`, `render`, `irq [times]`, `ppgtt`, `gem [times|cpu-only]`, `ctx`, `fence`, `uapi [cpu-only]`, `sync [cpu-only]`, `dev [cpu-only]`, `state` (the request queue's statistics: retired from the interrupt or by a waiter, time on the engine, forcewake wakes, each engine's registers), `all`; the DRM tests collect their output and write it at the end, since a write to a file on the PC's hard disk takes tens of ms and would stretch their timed parts; a count repeats quietly and prints only the first failure; the root-only `GpuTest` syscall, `src/cpu/syscall/gpu_test.cpp`), which prints the report it also logs. So far: the GGTT (upper half of BAR0, mapped write-combining at boot with the first 256 MiB of the aperture; the firmware's entries reclaimed as i915 does except the scanned-out plane and the top 2 MiB: the PC's firmware fills almost all of it, stolen memory one to one in the first 256 MiB; freed entries on a scratch page), buffer objects of RAM pages (clflushed: the display does not snoop the CPU caches), a plane A flip onto one, and command submission on the render and blitter engines (`intel_gen9_engine.cpp`: forcewake of the render/GT/media wells, execlists without the GuC, a fresh restore-inhibited context per run built from i915's `gen9_rcs_offsets`/`gen9_xcs_offsets` in `intel_gen9_logic.hpp`, engine reset through `RING_RESET_CTL` and `GDRST`, MI_USER_INTERRUPT over the GPU's MSI with the waiter sleeping like a blocking socket call so the handler can take the big kernel lock). A per-process 48-bit PPGTT (`intel_gen9_ppgtt.cpp`, after `gen8_ppgtt.c`: 4-level tables allocated as mappings need them, unmapped ranges through shared scratch tables to the scratch page; cached pages PPAT index 4, tables index 0) and i915's private PAT (`kGen9PrivatePat`, so far written only by `gpu-test ppgtt`) back 64-bit contexts (`contextDescriptor(..., fourLevel)`, the PML4 in PDP0); `gpu-test ppgtt` runs a batch from such an address space on each engine and reads its stores without flushing. Programs reach the GPU through `/dev/dri/renderD128` (`intel_gen9_drm.cpp`, opened by a path special case in `sys_open` like `/dev/ptmx`; ioctls and mmap are dispatched on the node in `sys_ioctl`/`sys_mmap_file`): Linux's i915 uAPI (`include/graphics/i915_drm.hpp`, numbers and structs from Linux's MIT headers, so libdrm/Mesa can use it unchanged), so far VERSION, GET_CAP, GETPARAM, GEM_CREATE/CLOSE, GEM_MMAP_OFFSET (WB/WC/UC) + mmap, SET_DOMAIN/SW_FINISH, BUSY/WAIT, sync objects (`Syncobj`, shared by the handles of any files and by their fds: CREATE/DESTROY/WAIT/RESET/SIGNAL, and timelines after Linux's dma_fence_chain: TIMELINE_SIGNAL/WAIT with WAIT_FOR_SUBMIT and WAIT_AVAILABLE, QUERY, TRANSFER; a point's fence is the join of every point up to it), GET_RESET_STATS and EXECBUFFER2 with softpinned objects only (no relocations), and what Mesa's i915 code asks besides (step 6d, from Mesa 24.3's `intel/dev`, `intel/common`, iris and anv): every GETPARAM it reads, answered as i915 on Skylake or as i915 does for what a part lacks (CS_TIMESTAMP_FREQUENCY from CTC_MODE, the fuses' EU/slice/subslice counts; no video engines, scheduler, HuC, PXP or perf), QUERY (topology from the fuses, `encodeGen9Topology`; the render and copy engines; one system-memory region of usable RAM; ENODEV for hwconfig, geometry, GuC), CONTEXT_GETPARAM/SETPARAM and CONTEXT_CREATE_EXT's SETPARAM chain (GTT_SIZE, RECOVERABLE, BANNABLE, PRIORITY only the default, VM, ENGINES maps of render/copy/empty slots that execbuffer's ring field then indexes, PERSISTENCE, RINGSIZE; SINGLE_TIMELINE contexts order their requests across engines), address spaces (`DrmVm`: each file has a default one, VM_CREATE/DESTROY make more, a context's is fixed once it has run, bindings live in it), REG_READ of the render timestamp, GET_APERTURE, SET/GET_TILING (metadata; no swizzling on Gen9), SET/GET_CACHING (uncached objects are mapped uncached and clflushed for the GPU and after SET_DOMAIN), MADVISE (nothing is purged yet) and GEM_CREATE_EXT (system memory only). A hang bans its context only when it is not recoverable (i915's rule; Mesa clears RECOVERABLE). Step 6d-2 adds fds: dma-bufs (PRIME_HANDLE_TO_FD/FD_TO_HANDLE: the object itself, so implicit fences hold across files; lseek gives the size, mmap maps it write-back, DMA_BUF_IOCTL_SYNC and EXPORT/IMPORT_SYNC_FILE, poll readable when nothing writes it, writable when nothing uses it), sync_files (one fence: poll readable once it is signaled, SYNC_IOC_MERGE, SYNC_IOC_FILE_INFO) and sync object fds (SYNCOBJ_HANDLE_TO_FD/FD_TO_HANDLE, also EXPORT/IMPORT_SYNC_FILE of a point), and execbuffer's timeline fences (I915_EXEC_USE_EXTENSIONS) and FENCE_IN/FENCE_OUT (EXECBUFFER2_WR). A `Fence` can be a join of others (`parts`, read through `poll()`). An fd in a DRM struct is the slot of a File handle (the handle is `1 << 48 | slot`; the 32-bit fields cannot hold a handle), and mlibc's ioctl wrapper (`Sysdeps<Ioctl>` in the instantos sysdeps, its `kFdFields` table and execbuffer's rsvd2) translates them to and from its own small fds, so libdrm and Mesa see ordinary fds. They reach other processes by inheritance or over AF_UNIX sockets (SCM_RIGHTS). The boot CPU's tick also checks for a hang (`IntelGen9Driver::timerTick`), so one is caught when nobody waits, e.g. a program blocked in poll on a sync_file. Step 6d-3: libdrm finds the node as on Linux (drmGetDevice2/drmGetDevices2): devfs lists `/dev/dri/renderD128` (char 226:128) while the node can open, and a RamFS at `/sys` holds what libdrm reads, written once by `drm::publishSysfs` (`intel_gen9_sysfs.cpp`): `devices/pci0000:00/0000:00:02.0` with vendor/device/subsystem_vendor/subsystem_device/revision/class/config/uevent, `subsystem` -> `/sys/bus/pci`, `driver`, `drm/renderD128` (dev, uevent), linked from `/sys/dev/char/226:128`, `/sys/class/drm/renderD128` and `/sys/bus/pci/devices` (absolute links). Without the GPU, `DrmWithoutGpu` writes the same layout with zero ids for the QEMU checks. Execbuffer does not wait: it queues a `Request` (`queueRequest` in `intel_gen9_engine.cpp`, i915's request queue) and returns. Each engine runs its queue in order, one request at a time, each once its dependency fences are signaled: implicit ones (every buffer object keeps its last reader per engine and last writer; a request waits for the last writer of what it uses and every last user of what it writes, unless EXEC_OBJECT_ASYNC) and explicit ones (the fence array's WAIT sync objects; SIGNAL ones get the request's fence). A request retires when its breadcrumb landed and the engine reported the switch-out (the context switch interrupt calls `processRequests` from the GPU's MSI; waiters call it too): its `Fence` is signaled, its references go (objects, context, the file's count, which keeps the file and its PPGTT alive). A request that makes no progress in 2 s (`kHangMs`, noticed by whoever waits or submits) is a hang: the engine is reset, the request fails with -EIO, its context loses its state and is banned (later execbuffers EIO, queued ones skipped; GET_RESET_STATS counts it), and requests depending on a failed fence are skipped with its error. GEM_CLOSE and moving a binding wait until the GPU is done with it. gpu-test's engine experiments claim the engines only when no request is queued (`claimEngines`), and requests queued meanwhile wait. A buffer object's pages are mapped `kSharedFrame` and its mmap region holds a reference (`MappedObject`, `include/memory/mapped_object.hpp`: split, fork and exec keep it), so closing a handle never frees mapped pages; `munmap` leaves `kSharedFrame` pages to their owner. `gpu-test gem cpu-only` (the root-only `DrmWithoutGpu` switch lets the node open without the GPU) checks everything but execbuffer in QEMU. Batches run in persistent contexts (`HwContext`, one per GEM context and engine, or per slot of its engine map as i915 has an intel_context per slot: iris maps its render and compute batches to two render-engine slots, and when they shared an image the compute batch's PIPELINE_SELECT/STATE_BASE_ADDRESS replaced the render batch's, so every draw after the first went nowhere; `CONTEXT_CREATE`/`DESTROY`, id 0 the default, all sharing the file's PPGTT): each has its own 16 KiB ring and image, the next run restores what the engine saved and only moves the ring window (`prepareContextResubmit`), and a run counts as done only once the breadcrumb landed and the context status buffer reported the switch to idle (the save comes after the store). Every new context starts as a copy of the engine's default image, recorded once on a freshly reset engine as i915's `__engines_record_defaults` does: on the render engine the context workarounds (one LRI, read back once) and the null-state batch (`intel_gen9_renderstate.hpp`, generated from i915's `gen9_renderstate.c`, relocated to its GGTT copy); so no context inherits another's registers. A render context restores with i915's indirect context batch (`emitGen9IndirectCtx`: the coherent-L3 flush, the SLM clear, three chicken bits), the MOCS tables are i915's Skylake ones (MMIO at engine set-up, LRI in the default context), and an image made from the default is not closed with MI_BATCH_BUFFER_END (only a restore-inhibited one is, as `set_offsets` does). Each request is i915's: an invalidation of the TLBs and read caches, the batch (non-privileged, PPGTT), a flush and a GGTT breadcrumb. `intel_gen9_wa.cpp` applies i915's Skylake lists (`intel_gen9_render_logic.hpp`: tables, emitters, fuse decoding): the GT workarounds and MCR steering once, the render engine's and the register whitelist (RING_FORCE_TO_NONPRIV: CS_CHICKEN1, HDC_CHICKEN1, ...) after every engine reset, R_PWR_CLK_STATE from the fuses in render contexts; each is read back and the counts logged (`[i915] GT workarounds: N set, N hold`). `gpu-test ctx` checks the default state, isolation, registers kept across 300 batches (ring wraps), the whitelist and PIPE_CONTROL from user batches; `gpu-test fence` the queue: a spinner batch (jumps to itself until the CPU writes MI_BATCH_BUFFER_END over it) keeps execbuffer, busy/wait, implicit and explicit fences honest, 1000 queued batches drain, and a spinner left running is caught as a hang. Forcewake is counted (the first get wakes the GT, the last put releases it); every engine set-up (`setUpEngine`, also after a reset) unmasks its interrupts again in `RING_IMR` (a reset masks them) and restarts the driver's context status buffer read pointer (`drainCsb` reads new events and moves the hardware's read pointer, as i915's `process_csb`). `WriteCombine` (`vmm.hpp`) is PAT entry 5, programmed on every CPU by `CPU::initialize`/`initializeSecondary`; the compositor's mapping of a device frame buffer uses it. Presentation is the one thing that writes to the GPU without gpu-test (`intel_gen9_display.cpp`, the `Display` syscall): the compositor gets two screen-sized scanout buffers (RAM, mapped write-combining) and plane A flips between them at vertical blank (`PLANE_SURF` is double-buffered; `PLANE_SURFLIVE` tells when it took); the firmware's framebuffer goes back on screen when the compositor exits and in the panic, kernel-exception and watchdog paths, which draw into it, and gpu-test's `flip` holds the compositor's flips back while its pattern shows.
- `drivers/`: virtio (gpu, net), USB (xHCI/OHCI), HID, net. `ipc/` holds kernel message queues and services.
- **Keyboard**: key events name the physical key by `KeyCode`, the USB HID usage (`syscall.hpp`, mirrored in ilibcxx; `docs/syscalls.md` under `Event`), whatever the keyboard; `text` is what it typed (US layout), empty for Enter/Backspace/Tab/Escape and other non-printing keys, so apps tell those by keycode. Every driver reports key changes to `Keyboard::keyChanged(keycode, down)` (`include/interrupts/keyboard.hpp`): PS/2 there too (set 1 with E0/E1 sequences; 0xAA is left Shift's break code, not filtered), USB (xHCI/OHCI) and I2C through `hidKeyboardReport`, which diffs each report against the last (modifier bits are the keys 0xE0-0xE7; a rollover report is ignored), the serial console as press+release with Shift/Ctrl around. The core keeps a bitmap of held keys, derives the modifiers from it, toggles Caps and Num Lock (on at boot; off turns the keypad into its navigation keys), sends Press and Release (no text) events, and repeats the last repeatable key held, 500 ms then every 33 ms, from `servicePendingInput` on the boot CPU's tick; keyboards' own repeats are dropped, so all repeat alike. Presses and repeats feed the console buffer (stdin without a terminal) with the bytes xterm would send (`keymap::consoleBytes`: C0 controls for Ctrl, ESC before the key for Alt, escape sequences with xterm's modifier parameter for the cursor and editing keys and F1-F12; Backspace is `\b`), each key's bytes queued whole or not at all. The lock lights follow `lockLeds()` (HID bit order: Num, Caps, Scroll): PS/2 sets them without waiting (0xED goes out, the light byte when its ACK arrives among the scancodes, up to 3 failures; synchronously at initialize), xHCI and OHCI send a SET_REPORT from their timer poll whenever a keyboard's lights differ, never from event handling (the xHCI control transfer drains the event ring while it waits). xHCI control transfers are waited for with interrupts off, bounded in time (5 s, Linux's USB_CTRL_SET_TIMEOUT; 100 ms for the lights, since the tick and everything waiting on the big kernel lock wait with them), and a failed one recovers ep0 (Reset Endpoint after an error such as a STALL, Stop Endpoint after a timeout, then Set TR Dequeue Pointer past the queued TRBs), as Linux does; an error event on any TRB of the transfer ends it. Without that, the PC's keyboard (it STALLs SET_PROTOCOL) made every later request time out, seconds each, and its lights never worked. I2C keyboards' lights are not set. `tools/qemu-rtl8168/build-qemu.sh` adds a `hid_kbd_set_leds` trace event to its QEMU so USB lights can be checked (PS/2 has `ps2_set_ledstate`). The pure tables (PS/2 → KeyCode, keypad, which keys repeat, US text, character → key) are `include/interrupts/keymap.hpp`.
- **Terminals and signals**: `spawn` gives the new program only the parent's file-like handles (files, pipes, sockets; not close-on-exec ones), so a PTY slave dup'd onto 0/1/2 reaches the shell; windows, surfaces, event queues and service connections are not inherited (a child holding them kept its parent's window on screen after the parent exited). `fork` copies every handle. There are no real process groups (mlibc's getpgrp is the pid), so whoever spawns a shell on a PTY makes it the foreground group (`TIOCSPGRP` on the master: the terminal app and `tools/bash-smoke/pty_launcher.c` do), or bash's job control waits. Signals with no handler kill the process except those Linux ignores (SIGCHLD, SIGCONT, SIGURG, SIGWINCH) and the stop signals (SIGSTOP/TSTP/TTIN/TTOU), which are ignored since nothing can stop a process. The terminal sends xterm sequences for the editing keys (the console's, but Backspace is DEL); `/etc/inputrc` (Ctrl+Left/Right move by word) (seeded by `main.cpp`) binds the ones readline does not know without terminfo.
- **Networking**: an IPv4 stack (ARP, ICMP, UDP, TCP) in `src/cpu/syscall/net.cpp` (wire layer) and `socket.cpp` (sockets, TCP state machine), with `NetDevice` drivers (`src/drivers/net`, probed in `probePriority` order). virtio-net (modern, or a transitional device through its modern interface) takes an MSI-X receive interrupt (`PCI::registerMSIXInterrupt`, balanced like MSI) and falls back to INTx. `e1000.cpp` covers Intel's 8254x, 8257x/82583, the PCH LOMs (82566 through the I219, with ULP/SMBus recovery for the PHY) and the igb parts (82575/6, 82580, I350, I210/I211; their own queue registers, queue enables, advanced descriptors); `rtl8169.cpp` the Realtek RTL8169/8111/8168/8101 family (the usual PC NIC; chip told apart by the TxConfig XID as in Linux's r8169; 8168G+ go through GPHY_OCP and have a receive gate to open). Both take MSI or INTx and map their BAR uncached through `PCI::mapMemoryBar`; rtl8139 is polled. QEMU has no RTL8168: `tools/qemu-rtl8168/build-qemu.sh` builds QEMU 8.2.2 with a model of one (`rtl8168.c`: receive gated, PHY powered down, link up 1.5 s after autonegotiation) into `~/qemu-rtl`, for `QEMU=~/qemu-rtl/bin/qemu-system-x86_64 QEMU_NIC=rtl8168`. The stack watches the link every 10 ms: a link that comes up gets its DHCP message at once, after an outage the lease is confirmed by broadcast (Rebinding), and `NetGetConfig` reports `linkUp` and the driver name (`netcfg` shows them). Everything the kernel logs is also kept in a 128 KiB ring (`Cereal::copyLog`, `KernelLog`), which the `dmesg` tool prints: on real hardware, without a serial port, that is where the drivers report. A receive handler calls `netDeviceInterrupt`, which drains the ring under the BKL. That is safe because kernel code runs with interrupts off (`SFMASK` clears IF), so an IRQ never lands inside the stack. An MSI/MSI-X handler EOIs before calling it, so it may switch to a woken process. INTx handlers must not EOI themselves: the shared dispatcher does that. The boot CPU's timer tick calls `netTimerTick` (only when it interrupted user mode or idle). It runs the ARP retries and TCP timers every 10 ms and also drains the ring then, in case an interrupt was missed; for a polled NIC it drains on every tick. network-manager no longer pumps; `NetProcessPackets` still works but is optional. Sends never wait for ARP: frames for an unresolved next hop wait in a small queue until the reply. Socket calls block in the kernel (`waitForSocketEvent`) unless the socket is `O_NONBLOCK` (`SOCK_NONBLOCK` or fcntl) or the call passes `MSG_DONTWAIT`, bounded by `SO_RCVTIMEO`/`SO_SNDTIMEO`. Any socket state change must call `Scheduler::wakeAllBlockedProcesses`, or a blocked reader can hang. The interface has no address until the kernel's DHCP client (in `net.cpp`, driven by the same 10 ms timer) gets a lease; until then connect/send/ping return `-ENETUNREACH`. The lease is renewed at T1 and rebound at T2. `NetGetConfig` reads the configuration and can wait for it to change; `NetSetConfig` (root) sets a static address, restarts or renews DHCP, or takes the interface down. network-manager follows those changes and writes `/etc/resolv.conf` and `/etc/hosts`; the boot code no longer writes resolv.conf. The stack answers pings, sends ICMP port unreachable for closed UDP ports and RST for closed TCP ports. Incoming ICMP errors fail a TCP connect (`-EHOSTUNREACH`, `-ECONNREFUSED`, ...), are kept as the reason if an established connection later times out, and fail the next call on a connected UDP socket, as on Linux. IP fragments are reassembled (4 datagrams at a time) and UDP datagrams above one frame leave fragmented. TCP (`socket.cpp`): send() appends to a 256 KiB queue and `tcpOutput` transmits from SND.NXT within min(cwnd, peer window); Reno/NewReno congestion control with IW10, RFC 6298 RTO with Karn's rule (200 ms floor), go-back-N on timeout, persist probes; SYNs carry MSS 1460 and window scale 3 (used only if the peer offers it too); 256 KiB receive buffer, trimming of overlapping segments, delayed ACKs (every second segment, 20 ms, immediate at the start of a connection, on PSH and for anything out of order); the announced window never shrinks and duplicate ACKs repeat it unchanged, or BSD-style senders such as slirp never fast-retransmit. Closing the last handle leaves an orphan that sends its queue and FIN (RST if unread data was dropped); segments to closed ports get a RST. `TCP_INFO` reports the state. `SendTo`/`RecvFrom` carry addresses (mlibc's `sendto`/`recvfrom`/`sendmsg`/`recvmsg` use them; a datagram is never split across iovecs); a connected UDP socket only hears from its peer. `SOCK_DGRAM` + `IPPROTO_ICMP` is a Linux-style ping socket.

**AF_UNIX sockets** (`src/cpu/syscall/unix_socket.cpp`): stream and seqpacket sockets bound to a path (kept in a kernel table after the cwd; no file appears in the file system, so `unlink` is not needed and does nothing to it) or an abstract name, listen/accept/connect, `socketpair` (also SOCK_DGRAM, with record boundaries; unconnected datagram sockets are not there), SO_PEERCRED, and SCM_RIGHTS: `SocketSendMsg`/`SocketRecvMsg` carry file-like handles (files, pipes, sockets, so dma-bufs and sync_files too) with the bytes, retained while in flight, installed when the bytes they came with are read (a stream read never runs into bytes carrying handles; a plain read drops them). Each receive queue holds 256 KiB. They are Socket handles; the handle's release function tells them from IPv4 sockets, and the socket syscalls in `socket.cpp` forward to them first. `read`/`write` on any socket are recv/send. mlibc's sendmsg/recvmsg try the AF_UNIX syscalls first (other sockets answer EOPNOTSUPP) and translate the fds; `unix-test` (in `net-tools`, `/bin/unix-test`) checks all of it, and a dma-buf written by a child when the GPU's node opens.

**Network tools** (`outside/iUserApps/net-tools/src/`): `ping`, `nslookup` (also installed as `host`, with its own DNS client), `netcfg` (show the interface, or `dhcp`/`renew`/`static`/`down` via `NetSetConfig`), `sntp` (SNTPv4 client; `-s` sets the clock) and `dmesg` (the kernel log) are mlibc C programs that CMake builds whenever `build/mlibc-root` exists and bundles into `/bin`. `tools/build-libdrm.sh` builds libdrm 2.4.123 (core only, static, every vendor library off) into the mlibc sysroot for the Mesa port, with the Linux uAPI headers it needs (`tools/libdrm-port/include`: `linux/types.h`, `asm/ioctl.h` with Linux's ioctl encoding) and `-D__linux__` (InstantOS follows Linux's DRM ABI), plus `drm-probe` (`tools/drm-probe/drm_probe.c`: device enumeration and identification, version, caps, sync objects, sync_files, timelines and PRIME through the real libdrm), bundled as `/bin/drm-probe` when built (rerun cmake); mlibc's sysdeps ship `sys/sysmacros.h` for it. `tools/build-libcxx.sh` builds LLVM 20.1.2's libc++, libc++abi and libunwind against mlibc (static, PIC, hermetic; no localization or filesystem; tree in WSL `~/libcxx-port`) into the sysroot, plus `cxx-smoke` (`tools/cxx-smoke`: containers, exceptions through libunwind, threads, thread_local; `/bin/cxx-smoke`). `tools/build-mesa.sh` cross-builds Mesa 24.3.4 (iris and softpipe for EGL/GLES/GL on the surfaceless platform, anv for Vulkan; no window system, LLVM, shader cache or xmlconfig; tree in WSL `~/mesa-port`) after a host build of its `intel_clc` (needs the WSL packages libclc-20-dev, libllvmspirvlib-20-dev, spirv-tools, libclang-cpp20-dev, libclang-20-dev, python3-mako, glslang-tools), with `-D__linux__ -D__unix__ -D__instantos__` and `asm/ioctl.h` force-included; `tools/mesa-port/patch-mesa.py` holds its source fixes (LLVM 20 in clc, a yield-based futex for `__instantos__`, no sched_getcpu/gettid). The libraries are built for `/lib/mlibc` and staged in `build/mesa-root`; stripped copies under their SONAMEs plus the tests `gl-offscreen` (`tools/mesa-tests`: EGL surfaceless, a GLES2 clear and shaded triangle read back; `gl-offscreen software` uses softpipe, which QEMU can run) and `vk-offscreen` (the anv ICD opened as the loader does, an image cleared and copied to a buffer), `gl-window` (GLES2 cube in a compositor window through the InstantOS EGL platform, `tools/mesa-port/platform_instantos.c`) and `vk-window` (the same cube in Vulkan, shaders compiled to SPIR-V by glslangValidator at build time). Vulkan presents to windows through `VK_INSTANTOS_surface`, a platform of our own (no Wayland): `tools/mesa-port/vulkan_instantos.h` (`vkCreateInstantOSSurfaceINSTANTOS` on a compositor window handle; `vulkan.h` turns `VK_USE_PLATFORM_INSTANTOS` on whenever `__instantos__` is defined) and `wsi_common_instantos.c` (FIFO, 3-8 linear BGRA dma-buf images, extent chosen by the swapchain; present commits and attaches like `eglSwapBuffers`, an image is acquired again once `SurfaceWaitIdle` says the compositor let it go), registered in Mesa's `vk.xml` by `patch-mesa.py` so the generated dispatch knows it. Both are paced by the kernel (FIFO with one frame queued): `WindowAttachSurface` of a GPU-buffer surface waits, at most 100 ms, until the compositor has listed the window with its current one (`SurfaceObject::isUnshown`, cleared in `releaseRetiredSurfaces`, which `WindowList` runs once a compositor pass), so no frame is replaced unseen and programs draw at the display's rate go in `build/mesa-root/initrd`, which CMake bundles (about 44 MB; the ISO's EFI image is 128 MiB for it). `tools/build-curl.sh` builds the curl CLI into `build/curl/curl`, with https:// when mbedTLS is in the sysroot (`tools/build-mbedtls.sh`, then `tools/build-zlib.sh` optionally; rerun cmake to bundle it).

**HTTPS and the clock**: TLS is mbedTLS 3.6 (static, in the mlibc sysroot), entropy from `getentropy` (the kernel's ChaCha20 CSPRNG seeded from RDSEED/RDRAND/TSC). `tools/fetch-cacert.sh` downloads Mozilla's CA bundle; CMake puts it in the initrd as `ssl/certs/ca-certificates.crt` and the kernel mounts the initrd's `ssl/` at `/etc/ssl`, so it is `/etc/ssl/certs/ca-certificates.crt`, curl's (and NetSurf's) default. Certificate checks need the date (and a clock that keeps pace): uptime comes from the TSC, also when the PIT drives the tick because the CPU lacks TSC-deadline mode (as under TCG), since counting PIT ticks loses those that arrive while interrupts are off. The wall clock is read from the RTC at boot, kept in nanoseconds (`GetUnixTimeNs`), and settable by root (`SetUnixTime`, mlibc `clock_settime`/`settimeofday`). network-manager runs `sntp -s` once when the interface first comes up (the DHCP option 42 server, else pool.ntp.org).

**Syscall ABI**: the `syscall` instruction, with the number in `rax` and arguments in `rbx, r10, rdx, r8, r9`. It returns `-errno` (older service syscalls may return `UINT64_MAX`). The source of truth is `SyscallNumber` in `include/cpu/syscall/syscall.hpp`. The userland mirror is `outside/iUserApps/outside/ilibcxx/include/syscall.hpp`. Shared structs are declared in both headers and must be kept in sync. `docs/syscalls.md` documents them (parts may lag the code).

**Desktop and NetSurf**: the graphics-compositor draws the desktop itself, including the window frames and the taskbar, in the "Base program style" below. Frames (`draw_window_frame` in `surface.cpp`): one rounded surface, a 40 px title bar with the app's icon (picked by title, `title_icon_index`) and name, minimize/maximize/close on the right as `/bin/icons` glyphs (the control under the pointer is `gWindowHover`; close turns red), a soft shadow from a per-focus alpha table. A window's repaint area includes its shadow (`window_damage_rect`). The taskbar (`taskbar_layout`/`taskbar_hit`/`taskbar_click` in `scene.cpp`) is one floating bar over a blurred copy of the wallpaper (`DesktopBackground::barBlur`, made when the wallpaper loads): the start button (no menu yet), the app tiles centred, the tray (network follows `NetGetConfig`; sound is always muted) and the clock. The tiles are the pinned apps (Terminal, Files, Wallpapers, Cube, Web; Super+T/F/B/C/W) and then one per window of any other app; an app's windows are matched by title. A dot marks a running app, a light tile and accent bar the focused one, and the hovered tile shows a tooltip (`gTaskbarHover`). A click starts the app, focuses its window (un-minimizing it) or minimizes it when it is the focused one. The taskbar is drawn over the windows and is hit-tested before them. Windows stay out of its way: maximize passes the work area to `WindowControl` (frame 8 px from the screen's edges, 12 px above the bar), and a new window that would reach under the bar is moved up or shrunk (`keepAboveTaskbar`) before its `window id=` line is logged. The "no internet" icon follows `NetGetConfig`. Keys go from the kernel to the focused window; the pointer goes only to the compositor, which forwards it (`WindowPostEvent`) to the window under it, or to the one a press in its content started, in content coordinates, and logs each new window (`[graphics.compositor] window id=… x= y= w= h= title=`). Only the compositor may map the framebuffer; `FBInfo` gives anyone the geometry. Once it does, the kernel console stops drawing (messages go to the log only); `Debug::takeScreenForReport` (panic, kernel exception) turns it back on and puts the firmware's framebuffer on screen. The compositor composes into a RAM scene buffer and presents through a backend (`backend.cpp`): `software` copies the changed area straight into the framebuffer (which can tear), `flip` (picked automatically on the Intel Gen9 display) collects the changes of one pass of the event loop and at `commit()` waits until the back buffer has left the screen, brings it up to date (each of the two buffers remembers the area it is missing and where its pointer was drawn) and flips, so the screen changes at most once a frame and a burst of pointer events costs one copy. The compositor is built on mlibc and libc++ when they are (step 8, `tools/build-compositor-mlibc.sh`, run by CMake; `-DINSTANTOS_COMPOSITOR_MLIBC=OFF` keeps the native one): the same sources plus the ilibcxx parts it uses (inline `syscall.hpp`, the ui drawing code, SVG, stb), with `graphics-compositor/mlibc/shim` mapping ilibcxx's `<cstring.hpp>`-style headers to the standard ones and `INSTANTOS_MLIBC` marking the differences (its network thread is a pthread). With Mesa's headers in the sysroot it has the `gl` backend (`gl_backend.cpp`, `INSTANTOS_COMPOSITOR_GL`; EGL/GLES 3 by dlopen): the whole scene drawn by the GPU every frame, wallpaper/contents/pointer as textures, window shadows (the CPU's falloff as a distance field), bodies, borders and rounded cuts in one shader, the CPU drawing only opaque parts (title bars via `draw_window_title`, the taskbar, the tooltip) into a side buffer that goes up as textures; GPU-buffer windows are sampled as they are (`SurfaceExportBuffer`, compositor-only, gives their dma-buf), shared-memory ones uploaded when committed (`SurfaceCacheEntry::generation`). It draws into the scanout buffers themselves (`Display ExportBuffer`: an uncached dma-buf borrowing a scanout buffer's pages; `instantos_handle_fd` makes a handle an mlibc fd) and is picked by itself on the Intel display; `--backend=gl` or `gl` in `/display.cfg` also takes the kernel's emulation (softpipe on the surfaceless platform, frames read back; about 16 s a frame under TCG, so only stills are checkable in QEMU; `NS_COMPOSITOR_BACKEND=gl` for the NetSurf suite). `/display.cfg` at the root of the disk (`F:\display.cfg` from Windows on the PC; `/etc` is always a RAM file system) holds `software`, `flip`, `gl` or `auto`: `software` is the way back if flips misbehave, `flip` also takes the kernel's emulation without the Intel display (a flip copies to the framebuffer), which is how the double buffering is checked in QEMU. NetSurf is `tools/build-{libpng,libjpeg,libcurl,netsurf-libs,netsurf}.sh` (host needs gperf, bison, flex, libpng-dev), then a cmake rerun; `/bin/netsurf` (`outside/iUserApps/netsurf/src/netsurf.c`) sizes the window to the screen and execs `/bin/nsfb -f instant`. Its surface, `tools/netsurf-port/libnsfb/instant.c`, is a compositor window; it maps the key codes of non-printing keys (arrows, Home/End, PgUp/PgDn, Insert/Delete, Esc, F-keys) to nsfb keys, passes Shift and Ctrl (per side) down and up as the real keys go, sends other keys down on press and repeat and up on release (remembering which nsfb key each press sent), and lets go of everything on FocusLost. `patches/netsurf-textinput.patch` gives the toolkit's text field Delete and keeps keys that type nothing out of it (it inserted a 0xFF byte for them). NetSurf's toolkit makes text from the key with its own UK shifted table and ignores Caps Lock, so a typed character still goes as the key that yields the kernel's text, with Shift lifted or added around it. Apps leave key presses with Super held to the compositor (its shortcuts); the native apps decide by keycode, text only for what is typed.

**UI library** (in ilibcxx, so in `libinstant.so`; every native GUI app is written on it, the old `instant::Window` is gone): `include/ui/graphics.hpp` is the drawing half, GDI's role. `ui::Color` (B,G,R,A, the surface pixel format; `ui::rgb(0xRRGGBB)`), `ui::Rect` (x, y, width, height; intersect/unite/contains), `ui::Canvas` over any pixel buffer with an origin and a clip (`sub()` moves the origin, `clipped()` narrows the clip): fill, rounded and top-rounded fills (anti-aliased), circle, frame, line, gradient, text (from a baseline, or fitted into a rect with `..`), images 1:1 or scaled, raw copies. `ui::Font` loads a TrueType file at one size and caches ASCII glyphs (stb_truetype; `Font::ui()` is the desktop's JetBrains Mono 13). `ui::Image` loads PNG/JPEG (stb_image) or SVG, resizes, recolours one-colour icons (`tint`), and has a canvas of its own. `svg_renderer` draws opaque pixels onto a background (it was made for framebuffers), so `load_svg` renders on black and on white and takes the alpha from the difference. Sources are `src/ui/*.cpp`, compiled `-O2` (the rest of the library is `-Oz`); stb is compiled in with static linkage and `NULL` redefined to `0` for it. The compositor draws only through it. Userland builds with `-fno-use-cxa-atexit`, so statics with destructors need libinstant's `atexit` (in `cxxabi.cpp`). `include/ui/window.hpp` is the window half, User32's role: an app derives from `ui::Window`, overrides `on_create`/`on_paint(canvas, dirty)`/`on_size`/`on_key_down`/`on_key_up`/`on_char`/`on_mouse_move|down|up` (with double-click counts)/`on_wheel`/`on_focus`/`on_timer`/`on_close`/`on_destroy`, and its `main` returns `ui::run<App>({ .width, .height, .title })` (an ordinary `add_user_app`). The loop sleeps in `poll` on the window's event queue, and on up to 4 handles the app `watch`es (a PTY, pipe or socket; `on_readable(handle)`, like Win32's MsgWaitForMultipleObjects), until the next event, readable handle or timer (`set_timer`); `invalidate(rect)` only marks, and once the queued events and due timers are handled the marked area is painted in one `on_paint` (clipped to it) and only it is committed. Keys with Super held never arrive; a key that types something and is not handled by `on_key_down` goes to `on_char` (not with Ctrl/Alt). A resize (Resized events, coalesced to the latest) makes a new surface of the new size (`surface_create`, `shared_map`, `window_attach_surface`, then `shared_free` on the old one, which now also takes surface handles and unmaps them), calls `on_size` and repaints everything. A dead surface's memory stays mapped in the compositor until its next `WindowList` (`IPCManager::retireSurfaceBacking`/`releaseRetiredSurfaces`), when no window can show it; the compositor drops cache entries for surfaces no window shows (`forget_unshown_surfaces`). Before that, every closed window's surface stayed mapped in the compositor for good. Painting goes to a private back buffer and the dirty area is then copied into the surface, so the compositor (which reads surfaces whenever it redraws) never shows a half-done paint; a new surface is attached only after its first full paint. `include/ui/controls.hpp`: controls are rectangles in a tree under the window (`root()`), made with their parent (`this` or a `Panel`) and usually members of the app's window class: `Panel`, `Label`, `Button` (default/cancel buttons: `set_default_button`/`set_cancel_button`, Enter/Escape), `CheckBox`, `TextBox` (single line, caret, selection, word moves), `ListBox` (rows from `row_text`/`draw_row` callbacks, its own `ScrollBar`, type-to-jump), `ScrollBar`, `ImageView` (keeps a scaled copy). Callbacks are `ui::Callback` (a lambda capturing up to 48 bytes; no `std::function`, which needs exceptions). Layout is WinForms': `set_anchor` keeps distances to parent edges recorded at `set_bounds` (set bounds in `on_create`, when the size is known), `set_dock` takes strips in creation order; it reruns on every resize. The window routes the mouse to the control under it (a press captures it until release; hover enter/leave), keys to the focused control then the window, then the defaults (Tab/Shift+Tab focus, Enter default button, Escape cancel button). `include/ui/theme.hpp`: `ui::theme()` has the shared colours, sizes and fonts (dark; see "Base program style"). `Font::ui()` is Stack Sans Text Regular at 13 px em (JetBrains Mono when the file is missing); glyph advances are rounded to the nearest pixel. `ui-demo` (`outside/iUserApps/ui-demo`, `/bin/ui-demo`, run it from the terminal) shows every control. The apps on it: cube, the wallpaper picker (a `ListBox` and a status line), the file browser (back/forward/up, a clickable breadcrumb and a search box that filters as you type in the toolbar; a Places sidebar of the top-level folders; Name/Kind/Size columns; a status line; type-to-jump, Enter or double-click opens, Backspace/Alt+Up up, Alt+Left/Right back/forward, Ctrl+F search, F5 rereads, Escape clears the search or closes) and the terminal (custom-painted cell grid repainting only the rows that changed; it `watch`es the PTY master, and a resize recomputes the grid and sends `TIOCSWINSZ`, so bash gets SIGWINCH). login has no window (it logs in root and starts the compositor).

**Userland** (`outside/iUserApps`, added via `add_subdirectory`): ELF binaries built with clang `-target x86_64-unknown-elf` + ld.lld by default, or with the GCC cross when `INSTANTOS_USERLAND_GCC=ON`. `ilibcxx` produces `libinstant.so` (the native libc/C++ runtime). `ld-instantos` is the dynamic linker, loaded at the fixed address `0x500000000000`. At boot the kernel launches these services from the initrd: input-manager, storage-manager, process-manager, network-manager, font-manager, session-manager, then `login`. The GUI parts (graphics-compositor, terminal, file-browser, …) run as clients of these services over IPC. Ported GNU software runs on **mlibc** instead, using the InstantOS sysdeps under `/lib/mlibc/`.

**Initrd**: the `make_initrd` custom command in `CMakeLists.txt` lists every file explicitly as `initrd/path:host/path` and packs them with `tools/mkInitrd`, a host tool built as an ExternalProject. Adding a userland binary or asset means adding it to that list and to `DEPENDS`. Initrd path names must stay under 64 characters. TCC, bash/mlibc and NetSurf entries are appended only when their artifacts exist or their option is on (`cmake/InstantOSTcc.cmake`, `cmake/InstantOSMlibc.cmake`).

**Ports & self-hosting tooling** (`tools/`): `build-*.sh` cross-build third-party software against mlibc or the TCC sysroot outside CMake. `gcc-port/`, `binutils-port/`, `gcc-selfhost/`, `buildworld/` and `tcc/` hold the bootstrap harnesses. Each one builds a dedicated headless ISO whose launcher drives the build in-OS and prints serial markers, for example `SELFHOST_GCC_STAGE2_EQ_STAGE3`. Port-specific notes are in `docs/mlibc.md`, `docs/tcc.md` and `docs/venus.md`.

## Base program style

Base programs are the ones the InstantOS developers write themselves: the desktop (graphics-compositor's taskbar and window frames), the native apps in `outside/iUserApps` (file browser, terminal, wallpaper picker, cube, ui-demo, …) and any new one. They must all follow this style. Ported software (bash, NetSurf, GNU tools) is exempt. The reference is the "Proposed desktop" frame in the Figma file "Desktop UI" (https://www.figma.com/design/0WkmT2egQP0E0ACLlqB0gq/Desktop-UI); when the rules and the frame disagree, ask.

Where it lives: `ui::theme()` holds the colours, sizes and fonts below (`font()`, `fontMedium()`, `fontSmall()`, `fontLabel()`, `fontMono()`; Stack Sans Text from `/bin/StackSansText-*.ttf`, OFL, sized in em pixels with `Font::load_em`). The line icons are `assets/icons/*.svg` (white, 24 units), installed in `/bin/icons` by a glob in `CMakeLists.txt`; load one with `Image::load_svg` and colour it with `Image::tint`. The library's controls already draw this way (flat icon buttons: `Button::set_icon`/`set_flat`; a search field: `TextBox::set_icon`; a sidebar list: `ListBox::set_sidebar`; section labels: `Label::set_font(&theme().fontLabel())`), and the file browser is the reference app. Not yet in it: a start menu, and the cube's own colours.

**How to build it**
- Write every app on the UI library (`ui::Window` and its controls). Never draw into a surface by hand or reimplement a control the library has; if one is missing, add it to the library so every app gets it.
- Take every colour, size and font from `ui::theme()`. Never write a colour literal in an app; add a token to the theme instead.
- Lay out with anchors and docking so the window works at any size, maximized included.

**Colours** (dark only; RGB)
- Surface: one colour for the whole window, title bar included, `#161d28`. Side panels `#121821`. Text fields and the search box `#0f141c`.
- Lines: dividers and borders are white at 6–10% opacity, never a solid grey.
- Text: primary `#e6edf3` (pure white only on a selected row), secondary `#8796a8`, disabled `#56606d`.
- Accent: `#398dd0`, for selection, focus, the start button and the focused-app bar. Lighter accent `#6cb6ee` for focus rings, the selection marker and accent icons. Danger `#e5484d` (close button hover, destructive actions).
- Selected row: accent at 22% opacity, radius 6, with a 3×16 px `#6cb6ee` bar at its left edge. Selected sidebar item: accent at 18%.
- File kinds by icon colour: folders `#6cb6ee`, programs `#7ee0a0`, other files `#aab4c0`. Colour the icon, not the name.

**Type**
- UI text is Stack Sans Text (the family of the clock's Stack Sans Notch): Regular 13 px for body and rows, Medium 13 for titles and selected items, 12 px for column headers and status bars, SemiBold 10.5 px uppercase with 8% letter spacing for section labels ("PLACES").
- JetBrains Mono only where text must line up in columns: the terminal, code and logs. Never for labels, titles or menus.
- Brand text (wordmark, clock) is Stack Sans Notch.

**Windows**
- Corner radius 12, a 1 px white-10% inner border, and a soft drop shadow (black 50%, 18 px down, 48 px blur). An unfocused window keeps the shape but its title and icons go to `#7d8794` and its shadow lightens.
- Title bar: 40 px, the same colour as the window. The app's 16 px icon and its name on the left, controls on the right: minimize, maximize, close, 46×40 each with 12 px line glyphs. Close turns `#e5484d` with a white glyph on hover.
- No window covers the taskbar: placement and maximize stop 12 px above it.
- A toolbar, when there is one, sits under the title bar (40 px, white-6% divider below), with icon buttons first, then a path bar or title field, search last.
- A status line at the bottom (28 px, secondary 12 px text, divider above) says what the window shows ("36 items · backgrounds selected").

**Controls and lists**
- Radius 6 for small things (rows, chips, sidebar items), 7–8 for fields and tooltips, 10 for app tiles, 12 for windows, 14 for the taskbar.
- Rows 30–32 px with a 16 px icon, padded 8 px from the list edge. Lists with more than one fact per item use columns with a header row (Name, Kind, Size …).
- Spacing on a 4 px grid: 8 px between related controls, 16 px around groups.
- Icons are 24-unit line icons drawn at 1.7–1.8 px stroke with round caps and joins (the Lucide look), shown at 16 px in content and 22 px in the taskbar. One colour each.
- Keyboard first, as Windows does: Tab moves the focus, Enter is the default button, Escape cancels or closes, letters jump in lists, F5 refreshes, Alt+Up goes to the parent, and toolbar buttons hand the focus back to the content.
- Tooltips: dark (`#0e131b` 95%), radius 8, 12 px Medium text, white-8% border, 8 px above what they describe.

**Desktop**
- One floating taskbar, 52 px high, 12 px from the screen's sides and bottom, radius 14, `#0e131b` at 86% with a background blur and a white-8% border.
- Left: the start button (36 px, radius 10, flat `#398dd0`, white "IO" in Stack Sans Notch Bold) and the "InstantOS" wordmark. Centre: pinned apps as 44×44 icon tiles. A running app has a 6×3 grey dot under it, the focused one a light tile (white 10%) and a 16×3 `#6cb6ee` bar. An open window has no separate button; its app's tile stands for it, and hovering shows the window title. Right: the tray (network, sound) then the time (Medium 14) over the date (11.5, secondary), right-aligned.
