# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

InstantOS is a graphical x86_64 hobby OS. It boots under UEFI, ships a C++ kernel, a userland of system "manager" services and GUI apps, and ports of real software (mlibc, GNU bash, coreutils, TinyCC, binutils, GCC, NetSurf). The long-term goal is a GCC that rebuilds itself inside InstantOS (see `roadmap.txt`, which tracks phases P0–P7). `TODO.md` lists the remaining work.

## Build environment

- The build runs on Linux, normally **WSL2 Ubuntu at `/mnt/d/projects/InstantOS`** (see `docs/wsl-setup.md`). The Windows checkout is the same tree. Scripts expect Arch-style OVMF paths (`/usr/share/edk2/x64/OVMF_{CODE,VARS}.4m.fd`). On Ubuntu, symlink them.
- Toolchain: clang/clang++, lld/lld-link, nasm, cmake, meson, xorriso, mtools, qemu. The bash/mlibc port needs clang >= 19 (`export PATH=/usr/lib/llvm-20/bin:$PATH`).
- Submodules are required, including the nested ones: `outside/iboot` (the bootloader), `outside/iUserApps` (userland), and inside it `outside/iUserApps/outside/{ilibcxx,mlibc,mlibc-sysdeps,tinycc}`.
- Keep heavy build trees (GCC/binutils) in WSL, not in the Windows `build/` directory, because C: is short on space.
- In this Windows checkout, `git status` shows almost every file as modified only because of file mode (755→644) and CRLF changes. Look at `git diff --stat` to find the real content changes.

## Commands

```bash
# Configure + build kernel, bootloader, userland, initrd, ISO -> build/iboot.iso
cmake -S . -B build [-DINSTANTOS_ENABLE_TCC=ON]
cmake --build build --target iso --parallel 4

# All in one: clean, optionally build mlibc+bash (cached in .bash-cache/; BASH_FORCE=1 rebuilds), build, run
./build.sh            # ENABLE_BASH=auto|0|1, ENABLE_TCC=auto|0|1

# Run in QEMU (serial -> serial.log, QEMU debug -> qemu.log)
./run.sh                                              # USB_MODE=xhci|ohci|none, GPU_MODE=plain|venus
QEMU_ACCEL=tcg QEMU_DISPLAY=none USB_MODE=xhci ./run.sh   # headless; WSL has no KVM, so always use tcg there
./run-win.sh                                          # Windows-native QEMU (WHPX) from Git Bash

# Kernel only (faster iteration)
cmake --build build --target INSTANTOS.EFI BOOTX64.EFI mkInitrd_proj
```

There is no lint step and there are no unit tests in the usual sense. Verification works like this:
- **Smoke tests** (`tools/run-*-smoke.sh`, e.g. `run-tcc-smoke.sh`, `run-coreutils-smoke.sh`, `run-bash-smoke.sh`, `run-pty-smoke.sh`, `run-storage-smoke.sh`, `run-network-smoke.sh`) build a custom ISO, boot it headless under QEMU with a timeout, and grep the serial log for marker strings. A run fails if the log contains `Unknown Instruction` or `User process crash`. Each script checks its prerequisites (bash, mlibc, tcc artifacts in `build/`) and says which `tools/build-*.sh` to run. To run a single test, run that one script.
- **In-OS feature suite**: `tools/run-os-testsuite.sh` builds the suite ISO (`tools/os-testsuite/build-testsuite-iso.sh`, whose `/bin/login` is `runner.c`) and an ext4 disk, boots them headless, and exits 0 only if the `[ostest] SCORE ... fail=0` line appears. `SKIP_BUILD=1` reuses the existing ISO; `SKIP_CMAKE=1` repacks only `runner.c`. The roadmap rule is that nothing counts as done until it runs headless in QEMU and this suite stays fully green.
- **Network suite**: `tools/run-net-suite.sh` boots an ISO whose `/bin/login` is `tools/net-suite/netsuite.c`, using the same build as the feature suite and the shared header `tools/os-testsuite/ostest.h`. It tests ping, UDP/TCP echo and HTTP downloads against `tools/net-suite/host_server.py`, which QEMU user networking exposes to the guest as 10.0.2.2. With `NET_INTERNET=1` it also does DNS and HTTP to example.com and runs the mlibc `dns-smoke`/`http-smoke` apps. `QEMU_NIC` swaps the NIC (for example `e1000`, `e1000e`, or `virtio-net-pci,vectors=0` to test INTx); with the default NIC the run also requires virtio-net's MSI-X line in the log. By default the NIC is a socket netdev to `host_server.py --link`, which relays frames to slirp (on a hub with a second socket netdev) and can drop, duplicate, reorder and delay TCP on the guest's request; it also plays a fake host, 10.0.2.77, that sends the ICMP errors, pings and probes slirp cannot and reports the options of our SYN (`NET_LINK=0` puts the NIC straight on slirp). The relay halves throughput, so compare speeds with `NET_LINK=0`. `run-os-testsuite.sh` takes the backend as `QEMU_NETDEV`. When bash and the network tools are built the suite also runs them (through `bash -c`, output captured) against the host, the fake host's DNS zone (`*.test`) and NTP server, and, with `NET_INTERNET=1`, example.com. With an mbedTLS curl it also tests https:// against `host_server.py --https`, using a test CA and server certificate it makes with openssl in `build/net-suite/tls` (bundled as `/etc/ssl/test-ca.pem`), plus the system bundle against real sites with `NET_INTERNET=1`. The host also pulls the guest's cable over QMP (`GET /linkflap/MS` -> `set_link net0`) and checks the link and lease come back, and the suite checks `KernelLog`/`dmesg`. Any QEMU NIC model works (`e1000`, `e1000e`, `igb`, `rtl8168` with the custom QEMU). It passes only with `fail=0`; `GAP:` lines record known shortcomings without failing the run.
- **NetSurf suite**: `tools/run-netsurf-suite.sh` boots the real system image (cmake writes its entry list to `build/initrd-entries.txt`) with `/bin/login` swapped for `tools/netsurf-suite/driver.c`, which gives NetSurf a homepage on `host_server.py --https` and starts the compositor. `tools/netsurf-suite/drive.py` then works the VM over QMP like a user (relative USB mouse moved in steps after homing at (0,0), `send-key`): clicks the taskbar's Web slot, checks the page, stylesheet and image are fetched over HTTPS (`--request-log`) and drawn (exact colours from `tools/netsurf-suite/pages/style.css` in screendumps), clicks a link, types a URL, types another with Shift held over several keys (`input-send-event`), and edits one with Home/End/Left/Delete. Screendumps and logs land in `build/netsurf-suite`. QMP's Unix socket must live outside `/mnt/d` (drvfs cannot hold one).
- Every QEMU launcher takes `QEMU_SMP` for the CPU count. The default is 2, except 1 for `run-os-testsuite.sh` and `run-win.sh`.
- **Keyboard suite**: `tools/run-kbd-suite.sh` boots QEMU with each keyboard (`KBD_MODES`, default `ps2 usb ohci`: the i8042 alone, usb-kbd on xHCI, on OHCI) and presses keys over QMP (`tools/kbd-suite/drive.py`). A probe image (the feature suite's, `/bin/login` = `tools/kbd-suite/console_probe.c`) prints each console read in hex, which is compared with the bytes every kind of key must give. The system image (`build/iboot.iso`, needs bash and curl) opens the terminal and edits bash command lines with the keys (arrows, Home/End, Delete, Ctrl+A/K/W/C, Ctrl+Left/Right, Alt+B, held Shift, repeat, keypad, Caps/Num Lock); each line is a curl to `host_server.py`, whose request log shows what bash ran. When the QEMU (`QEMU`, default `~/qemu-rtl`'s if built) has the `hid_kbd_set_leds` trace event it also checks the lock lights. `KBD_PARTS=console|terminal` runs one half. Passes only with `[kbdsuite] SCORE ... fail=0`.
- **Host-side fixtures**: `tools/run-acpi-fixtures.sh` (ACPI table parsing), `tools/run-keymap-fixtures.sh` (the keyboard tables in `keymap.hpp`: PS/2 codes, repeat, keypad, US text, console bytes for every key and modifier) and `tools/ext4-fixtures/`.

## Architecture

**Boot chain:** UEFI firmware → `BOOTX64.EFI` (iboot submodule) → `INSTANTOS.EFI`. The kernel is itself a PE/COFF UEFI application (clang `-target x86_64-unknown-windows`, `lld-link`, entry symbol `InstantOS`, NASM `win64` objects). iboot passes a `BootInfo` that holds the framebuffer, memory map, RSDP and initrd location. `iboot::headers` provides the shared BootInfo types.

**Kernel** (`src/`, headers in `include/` mirror the same tree). `CMakeLists.txt` globs every `src/**/*.cpp|*.asm`, so new files need no CMake edits. It is freestanding C++23: no RTTI, no exceptions, no libc/libstdc++, built with `-Oz -fno-inline`. Use the in-tree helpers in `include/common/`. Most subsystems are singletons reached through `X::get()`. `src/main.cpp` (`InstantOS(BootInfo*)`) sets the init order: console → GDT → CPU features → PMM/VMM → 16 MiB heap → ACPI → APIC → scheduler → timers → USB/I2C input → GPU (virtio-gpu, VirGL/Venus, SVGA, Intel probes) → syscalls → SMP AP startup (`src/cpu/smp.cpp`; the APs wait until `SMP::startScheduling()` at the end of boot) → users/sessions → VFS mounts → seeding of `/etc` files → launch of the userland services. The same sources also build `INSTANTOS_INPUT_PROBE.EFI` (with `INPUT_PROBE_ONLY=1`), a diagnostic kernel for input hardware.
- `cpu/`: ACPI (with an AML interpreter; pure table logic lives in `acpi_tables.hpp` so host fixtures can share it), APIC/IOAPIC, GDT/IDT/ISRs, per-CPU data, `process/` (scheduler, context switch, ELF/PE exec), `syscall/` (split by area: fs, mem, proc, …), tty/PTY, users/sessions.
- **SMP and locking:** every CPU listed in the MADT runs the scheduler. All kernel code runs under one recursive big kernel lock (`include/cpu/klock.hpp`). It is taken at syscall, IRQ and exception entry, dropped when returning to user mode (including the trampolines in `process/switch.cpp`) and at the top of `idleLoop`, and handed across `switchContext` by `Scheduler::switchTo`. Kernel code must not wait for an interrupt while holding it. In the kernel, GS always points at the executing CPU's `PerCPUData` (`include/cpu/percpu.hpp`), so never cache per-CPU pointers across a context switch. Threads of one address space run on several CPUs at once, so any change that removes or narrows a mapping must go through `TLB::shootdown` (`include/cpu/tlb.hpp`). The VMM unmap/protect/COW paths and fork already do. Do not free a frame or page table until the shootdown has returned, and never spin with interrupts off without calling `TLB::pollPending()`. Widening a mapping needs no shootdown: the page-fault handler retries stale-TLB faults. `exec` sends SIGKILL to the caller's other threads and waits until they are reaped (`Scheduler::killSiblingThreads`) before it swaps the image, because their teardown unmaps from the shared address space. A timer or IPI that interrupts user mode acts on a pending SIGKILL (`Process::terminateIfKilled`). Like Linux `exit_group`, `Exit`, a fatal signal or a crash in any thread ends the whole process (`Scheduler::exitThreadGroup`): the main thread keeps the exit status, and `wait` reports it only once every thread has been reaped. `ThreadExit` ends just the calling thread, except on the main thread, where it acts like `Exit`. Two things already run without the BKL:
  - Scheduler ticks that would change nothing (`Scheduler::tickIsNoop`, plus the boot CPU's `tryEnter` tick).
  - Block-backed filesystems. ext4/FAT32 VNode ops, mount, format and the AHCI driver run under the storage lock (`include/fs/storage/storage_lock.hpp`), and syscalls on the `storageMayRunUnlocked` list (`syscall.cpp`) release the BKL for the whole operation. Code reachable from there may only use subsystems with their own locks (heap, PMM, console), never BKL-protected state. Lock order is BKL, then storage. A syscall added to that list must hold no unpinned pointer to BKL state across VFS calls; fds are pinned with `PinnedFd`.

  `KLOCK_PROFILE` in `klock.cpp` prints per-entry-site contention.

  Device interrupts are spread over the APs: `APICManager::mapGSI` and `PCI::registerMSIInterrupt` record each route with `IRQBalance` (`include/cpu/apic/irq_balance.hpp`), and `SMP::startScheduling` moves them round-robin off the boot CPU, which keeps the PIT tick. IRQ handlers must therefore work on any CPU. Each thread has a CPU affinity mask (`Process::cpuAffinity`, the `SchedSetAffinity`/`SchedGetAffinity`/`GetCpu`/`CpuInfo` syscalls) that `Scheduler::getNextProcess` honours. mlibc's `sysconf(_SC_NPROCESSORS_ONLN)` asks `CpuInfo`.
- `fs/`: a VFS with initrd (read-only `/bin` and `/lib`), RamFS (`/tmp`), devfs, FAT32 and ext4 on AHCI with partition parsing.
- `drivers/`: virtio (gpu, net), USB (xHCI/OHCI), HID, net. `ipc/` holds kernel message queues and services.
- **Keyboard**: key events name the physical key by `KeyCode`, the USB HID usage (`syscall.hpp`, mirrored in ilibcxx; `docs/syscalls.md` under `Event`), whatever the keyboard; `text` is what it typed (US layout), empty for Enter/Backspace/Tab/Escape and other non-printing keys, so apps tell those by keycode. Every driver reports key changes to `Keyboard::keyChanged(keycode, down)` (`include/interrupts/keyboard.hpp`): PS/2 there too (set 1 with E0/E1 sequences; 0xAA is left Shift's break code, not filtered), USB (xHCI/OHCI) and I2C through `hidKeyboardReport`, which diffs each report against the last (modifier bits are the keys 0xE0-0xE7; a rollover report is ignored), the serial console as press+release with Shift/Ctrl around. The core keeps a bitmap of held keys, derives the modifiers from it, toggles Caps and Num Lock (on at boot; off turns the keypad into its navigation keys), sends Press and Release (no text) events, and repeats the last repeatable key held, 500 ms then every 33 ms, from `servicePendingInput` on the boot CPU's tick; keyboards' own repeats are dropped, so all repeat alike. Presses and repeats feed the console buffer (stdin without a terminal) with the bytes xterm would send (`keymap::consoleBytes`: C0 controls for Ctrl, ESC before the key for Alt, escape sequences with xterm's modifier parameter for the cursor and editing keys and F1-F12; Backspace is `\b`), each key's bytes queued whole or not at all. The lock lights follow `lockLeds()` (HID bit order: Num, Caps, Scroll): PS/2 sets them without waiting (0xED goes out, the light byte when its ACK arrives among the scancodes, up to 3 failures; synchronously at initialize), xHCI and OHCI send a SET_REPORT from their timer poll whenever a keyboard's lights differ, never from event handling (the xHCI control transfer drains the event ring while it waits). I2C keyboards' lights are not set. `tools/qemu-rtl8168/build-qemu.sh` adds a `hid_kbd_set_leds` trace event to its QEMU so USB lights can be checked (PS/2 has `ps2_set_ledstate`). The pure tables (PS/2 → KeyCode, keypad, which keys repeat, US text, character → key) are `include/interrupts/keymap.hpp`.
- **Terminals and signals**: there are no real process groups (mlibc's getpgrp is the pid), so whoever spawns a shell on a PTY makes it the foreground group (`TIOCSPGRP` on the master: the terminal app and `tools/bash-smoke/pty_launcher.c` do), or bash's job control waits. Signals with no handler kill the process except those Linux ignores (SIGCHLD, SIGCONT, SIGURG, SIGWINCH) and the stop signals (SIGSTOP/TSTP/TTIN/TTOU), which are ignored since nothing can stop a process. The terminal sends xterm sequences for the editing keys (the console's, but Backspace is DEL); `/etc/inputrc` (Ctrl+Left/Right move by word) (seeded by `main.cpp`) binds the ones readline does not know without terminfo.
- **Networking**: an IPv4 stack (ARP, ICMP, UDP, TCP) in `src/cpu/syscall/net.cpp` (wire layer) and `socket.cpp` (sockets, TCP state machine), with `NetDevice` drivers (`src/drivers/net`, probed in `probePriority` order). virtio-net (modern, or a transitional device through its modern interface) takes an MSI-X receive interrupt (`PCI::registerMSIXInterrupt`, balanced like MSI) and falls back to INTx. `e1000.cpp` covers Intel's 8254x, 8257x/82583, the PCH LOMs (82566 through the I219, with ULP/SMBus recovery for the PHY) and the igb parts (82575/6, 82580, I350, I210/I211; their own queue registers, queue enables, advanced descriptors); `rtl8169.cpp` the Realtek RTL8169/8111/8168/8101 family (the usual PC NIC; chip told apart by the TxConfig XID as in Linux's r8169; 8168G+ go through GPHY_OCP and have a receive gate to open). Both take MSI or INTx and map their BAR uncached through `PCI::mapMemoryBar`; rtl8139 is polled. QEMU has no RTL8168: `tools/qemu-rtl8168/build-qemu.sh` builds QEMU 8.2.2 with a model of one (`rtl8168.c`: receive gated, PHY powered down, link up 1.5 s after autonegotiation) into `~/qemu-rtl`, for `QEMU=~/qemu-rtl/bin/qemu-system-x86_64 QEMU_NIC=rtl8168`. The stack watches the link every 10 ms: a link that comes up gets its DHCP message at once, after an outage the lease is confirmed by broadcast (Rebinding), and `NetGetConfig` reports `linkUp` and the driver name (`netcfg` shows them). Everything the kernel logs is also kept in a 128 KiB ring (`Cereal::copyLog`, `KernelLog`), which the `dmesg` tool prints: on real hardware, without a serial port, that is where the drivers report. A receive handler calls `netDeviceInterrupt`, which drains the ring under the BKL. That is safe because kernel code runs with interrupts off (`SFMASK` clears IF), so an IRQ never lands inside the stack. An MSI/MSI-X handler EOIs before calling it, so it may switch to a woken process. INTx handlers must not EOI themselves: the shared dispatcher does that. The boot CPU's timer tick calls `netTimerTick` (only when it interrupted user mode or idle). It runs the ARP retries and TCP timers every 10 ms and also drains the ring then, in case an interrupt was missed; for a polled NIC it drains on every tick. network-manager no longer pumps; `NetProcessPackets` still works but is optional. Sends never wait for ARP: frames for an unresolved next hop wait in a small queue until the reply. Socket calls block in the kernel (`waitForSocketEvent`) unless the socket is `O_NONBLOCK` (`SOCK_NONBLOCK` or fcntl) or the call passes `MSG_DONTWAIT`, bounded by `SO_RCVTIMEO`/`SO_SNDTIMEO`. Any socket state change must call `Scheduler::wakeAllBlockedProcesses`, or a blocked reader can hang. The interface has no address until the kernel's DHCP client (in `net.cpp`, driven by the same 10 ms timer) gets a lease; until then connect/send/ping return `-ENETUNREACH`. The lease is renewed at T1 and rebound at T2. `NetGetConfig` reads the configuration and can wait for it to change; `NetSetConfig` (root) sets a static address, restarts or renews DHCP, or takes the interface down. network-manager follows those changes and writes `/etc/resolv.conf` and `/etc/hosts`; the boot code no longer writes resolv.conf. The stack answers pings, sends ICMP port unreachable for closed UDP ports and RST for closed TCP ports. Incoming ICMP errors fail a TCP connect (`-EHOSTUNREACH`, `-ECONNREFUSED`, ...), are kept as the reason if an established connection later times out, and fail the next call on a connected UDP socket, as on Linux. IP fragments are reassembled (4 datagrams at a time) and UDP datagrams above one frame leave fragmented. TCP (`socket.cpp`): send() appends to a 256 KiB queue and `tcpOutput` transmits from SND.NXT within min(cwnd, peer window); Reno/NewReno congestion control with IW10, RFC 6298 RTO with Karn's rule (200 ms floor), go-back-N on timeout, persist probes; SYNs carry MSS 1460 and window scale 3 (used only if the peer offers it too); 256 KiB receive buffer, trimming of overlapping segments, delayed ACKs (every second segment, 20 ms, immediate at the start of a connection, on PSH and for anything out of order); the announced window never shrinks and duplicate ACKs repeat it unchanged, or BSD-style senders such as slirp never fast-retransmit. Closing the last handle leaves an orphan that sends its queue and FIN (RST if unread data was dropped); segments to closed ports get a RST. `TCP_INFO` reports the state. `SendTo`/`RecvFrom` carry addresses (mlibc's `sendto`/`recvfrom`/`sendmsg`/`recvmsg` use them; a datagram is never split across iovecs); a connected UDP socket only hears from its peer. `SOCK_DGRAM` + `IPPROTO_ICMP` is a Linux-style ping socket.

**Network tools** (`outside/iUserApps/net-tools/src/`): `ping`, `nslookup` (also installed as `host`, with its own DNS client), `netcfg` (show the interface, or `dhcp`/`renew`/`static`/`down` via `NetSetConfig`), `sntp` (SNTPv4 client; `-s` sets the clock) and `dmesg` (the kernel log) are mlibc C programs that CMake builds whenever `build/mlibc-root` exists and bundles into `/bin`. `tools/build-curl.sh` builds the curl CLI into `build/curl/curl`, with https:// when mbedTLS is in the sysroot (`tools/build-mbedtls.sh`, then `tools/build-zlib.sh` optionally; rerun cmake to bundle it).

**HTTPS and the clock**: TLS is mbedTLS 3.6 (static, in the mlibc sysroot), entropy from `getentropy` (the kernel's ChaCha20 CSPRNG seeded from RDSEED/RDRAND/TSC). `tools/fetch-cacert.sh` downloads Mozilla's CA bundle; CMake puts it in the initrd as `ssl/certs/ca-certificates.crt` and the kernel mounts the initrd's `ssl/` at `/etc/ssl`, so it is `/etc/ssl/certs/ca-certificates.crt`, curl's (and NetSurf's) default. Certificate checks need the date (and a clock that keeps pace): uptime comes from the TSC, also when the PIT drives the tick because the CPU lacks TSC-deadline mode (as under TCG), since counting PIT ticks loses those that arrive while interrupts are off. The wall clock is read from the RTC at boot, kept in nanoseconds (`GetUnixTimeNs`), and settable by root (`SetUnixTime`, mlibc `clock_settime`/`settimeofday`). network-manager runs `sntp -s` once when the interface first comes up (the DHCP option 42 server, else pool.ntp.org).

**Syscall ABI**: the `syscall` instruction, with the number in `rax` and arguments in `rbx, r10, rdx, r8, r9`. It returns `-errno` (older service syscalls may return `UINT64_MAX`). The source of truth is `SyscallNumber` in `include/cpu/syscall/syscall.hpp`. The userland mirror is `outside/iUserApps/outside/ilibcxx/include/syscall.hpp`. Shared structs are declared in both headers and must be kept in sync. `docs/syscalls.md` documents them (parts may lag the code).

**Desktop and NetSurf**: the graphics-compositor draws the desktop itself, including the taskbar. Its centre pill (`taskbar_layout`/`taskbar_hit` in `scene.cpp`) holds the launchers (Terminal, Files, Walls, Cube, Web; Super+T/F/B/C/W; a mark under the ones whose window is open, matched by title) and, after a divider, a button per open window in the order they opened: the focused one highlighted, minimized ones greyed; a click focuses (and so un-minimizes) a window, or minimizes the focused one. The pill grows with the windows up to the room between the side pills, the buttons and then the launchers shrinking. The taskbar is drawn over the windows and is hit-tested before them. desktop-shell is bundled but not started. The "no internet" icon follows `NetGetConfig`. Keys go from the kernel to the focused window; the pointer goes only to the compositor, which forwards it (`WindowPostEvent`) to the window under it, or to the one a press in its content started, in content coordinates, and logs each new window (`[graphics.compositor] window id=… x= y= w= h= title=`). Only the compositor may map the framebuffer; `FBInfo` gives anyone the geometry. NetSurf is `tools/build-{libpng,libjpeg,libcurl,netsurf-libs,netsurf}.sh` (host needs gperf, bison, flex, libpng-dev), then a cmake rerun; `/bin/netsurf` (`outside/iUserApps/netsurf/src/netsurf.c`) sizes the window to the screen and execs `/bin/nsfb -f instant`. Its surface, `tools/netsurf-port/libnsfb/instant.c`, is a compositor window; it maps the key codes of non-printing keys (arrows, Home/End, PgUp/PgDn, Insert/Delete, Esc, F-keys) to nsfb keys, passes Shift and Ctrl (per side) down and up as the real keys go, sends other keys down on press and repeat and up on release (remembering which nsfb key each press sent), and lets go of everything on FocusLost. `patches/netsurf-textinput.patch` gives the toolkit's text field Delete and keeps keys that type nothing out of it (it inserted a 0xFF byte for them). NetSurf's toolkit makes text from the key with its own UK shifted table and ignores Caps Lock, so a typed character still goes as the key that yields the kernel's text, with Shift lifted or added around it. Apps leave key presses with Super held to the compositor (its shortcuts); the native apps decide by keycode, text only for what is typed.

**UI library** (in ilibcxx, so in `libinstant.so`; being built to replace `instant::Window` and the apps' hand-rolled drawing): `include/ui/graphics.hpp` is the drawing half, GDI's role. `ui::Color` (B,G,R,A, the surface pixel format; `ui::rgb(0xRRGGBB)`), `ui::Rect` (x, y, width, height; intersect/unite/contains), `ui::Canvas` over any pixel buffer with an origin and a clip (`sub()` moves the origin, `clipped()` narrows the clip): fill, rounded and top-rounded fills (anti-aliased), circle, frame, line, gradient, text (from a baseline, or fitted into a rect with `..`), images 1:1 or scaled, raw copies. `ui::Font` loads a TrueType file at one size and caches ASCII glyphs (stb_truetype; `Font::ui()` is the desktop's JetBrains Mono 13). `ui::Image` loads PNG/JPEG (stb_image) or SVG, resizes, and has a canvas of its own. Sources are `src/ui/*.cpp`, compiled `-O2` (the rest of the library is `-Oz`); stb is compiled in with static linkage and `NULL` redefined to `0` for it. The compositor draws only through it. Userland builds with `-fno-use-cxa-atexit`, so statics with destructors need libinstant's `atexit` (in `cxxabi.cpp`). `include/ui/window.hpp` is the window half, User32's role: an app derives from `ui::Window`, overrides `on_create`/`on_paint(canvas, dirty)`/`on_size`/`on_key_down`/`on_key_up`/`on_char`/`on_mouse_move|down|up` (with double-click counts)/`on_wheel`/`on_focus`/`on_timer`/`on_close`/`on_destroy`, and its `main` returns `ui::run<App>({ .width, .height, .title })` (an ordinary `add_user_app`, not `add_instant_window_app`). The loop sleeps in `poll` on the window's event queue until the next event or timer (`set_timer`); `invalidate(rect)` only marks, and once the queued events and due timers are handled the marked area is painted in one `on_paint` (clipped to it) and only it is committed. Keys with Super held never arrive; a key that types something and is not handled by `on_key_down` goes to `on_char` (not with Ctrl/Alt). A resize (Resized events, coalesced to the latest) makes a new surface of the new size (`surface_create`, `shared_map`, `window_attach_surface`, then `shared_free` on the old one, which now also takes surface handles and unmaps them), calls `on_size` and repaints everything. A dead surface's memory stays mapped in the compositor until its next `WindowList` (`IPCManager::retireSurfaceBacking`/`releaseRetiredSurfaces`), when no window can show it; the compositor drops cache entries for surfaces no window shows (`forget_unshown_surfaces`). Before that, every closed window's surface stayed mapped in the compositor for good. The cube and the wallpaper picker are on `ui::Window`.

**Userland** (`outside/iUserApps`, added via `add_subdirectory`): ELF binaries built with clang `-target x86_64-unknown-elf` + ld.lld by default, or with the GCC cross when `INSTANTOS_USERLAND_GCC=ON`. `ilibcxx` produces `libinstant.so` (the native libc/C++ runtime). `ld-instantos` is the dynamic linker, loaded at the fixed address `0x500000000000`. At boot the kernel launches these services from the initrd: input-manager, storage-manager, process-manager, network-manager, font-manager, session-manager, then `login`. The GUI parts (graphics-compositor, desktop-shell, terminal, file-browser, …) run as clients of these services over IPC. Ported GNU software runs on **mlibc** instead, using the InstantOS sysdeps under `/lib/mlibc/`.

**Initrd**: the `make_initrd` custom command in `CMakeLists.txt` lists every file explicitly as `initrd/path:host/path` and packs them with `tools/mkInitrd`, a host tool built as an ExternalProject. Adding a userland binary or asset means adding it to that list and to `DEPENDS`. Initrd path names must stay under 64 characters. TCC, bash/mlibc and NetSurf entries are appended only when their artifacts exist or their option is on (`cmake/InstantOSTcc.cmake`, `cmake/InstantOSMlibc.cmake`).

**Ports & self-hosting tooling** (`tools/`): `build-*.sh` cross-build third-party software against mlibc or the TCC sysroot outside CMake. `gcc-port/`, `binutils-port/`, `gcc-selfhost/`, `buildworld/` and `tcc/` hold the bootstrap harnesses. Each one builds a dedicated headless ISO whose launcher drives the build in-OS and prints serial markers, for example `SELFHOST_GCC_STAGE2_EQ_STAGE3`. Port-specific notes are in `docs/mlibc.md`, `docs/tcc.md` and `docs/venus.md`.
